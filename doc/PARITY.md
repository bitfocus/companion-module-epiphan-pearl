# Companion parity map (Epiphan Pearl)

This file maps the module onto the behaviour reference `C:\Users\RyanHaynes\Desktop\Epiphan Tools\Claude Apps\Vibe Coded Apps\Epiphan-StreamDeck\docs\COMPANION-PARITY.md` (the Epiphan Stream Deck plugins, verified against a Pearl-2 on firmware 10.2.5.110 and an EC20 on firmware 10.2.3.37 on 2026-09-04). ## Decisions taken

- **D1 One action per Stream Deck action.** Phase 3 items named as separate actions (`eventToggle`, `inputAudioGainNudge`, `inputAudioDelayNudge`, "…(confirm)" actions, `inputLevelMeter`) are realised as options of the target-set actions/feedbacks so the control set stays exactly the Stream Deck set: the event toggle is `event` with `op: toggle`; the gain/delay nudges are `audio` with `control: gain|delay`; the confirm step is a `confirm` checkbox (default on) on `power`, `preset` (Pearl apply) and `storage` (eject), and on the EC20 `preset` action for `op: clear`; the audio meter is the advanced feedback `audio`.
- **D2 Hold-to-confirm.** Companion has no hold arc. Actions with `confirm: true` require a second press of the same button (same `controlId`) within 3 s; the first press arms the variable `confirm_hint` = `Press again to confirm` (and the boolean feedback `confirm_pending`, keyed by controlId) and does nothing on the device; the timer clears both. HELP documents Companion's own press-duration groups (add the action under "Release after N ms", untick confirm) as the alternative that reproduces the Stream Deck hold.
- **D3 Motion stop.** Companion has no key-up event for an action, so hold-mode motion needs an explicit stop: the EC20 `ptz.direction`, `zoom.direction` and `focus.op` value sets gain one extra value `stop` ("Stop (bind on release)"). Shipped presets put the start on `down` and `stop` on `up`.
- **D4 Rotary.** Presets with `options.rotaryActions: true` and `rotate_left` / `rotate_right` steps reuse the same actions: `audio` (direction down/up), `ptz` (mode step, left/right), `zoom` (mode step = 120 ms burst), `focus` (near/far bursts), `wb` / `exposure` / `picture` (direction dec/inc). Ticks arriving within 150 ms of each other are coalesced per controlId into one command (nudges add up their steps; bursts re-arm their stop timer). Push = the action with the "push" op (ptz home, focus/zoom onepush, exposure/picture reset, wb onepush, audio control none = re-read).
- **D5 Composite ids for channel-dependent lists.** Companion dropdowns cannot depend on another option, so `layout.layoutId` holds `<cid>-<lid>` and `stream.publisherId` holds `<cid>-<pid>` or `<cid>-all` (labels `Channel – Layout`, `Channel – Publisher (type)`, `Channel – All publishers`). `channelId` is kept as the Stream Deck setting key and is used when the composite cannot be parsed (e.g. `layoutIdManual`); when both are present the composite's channel wins. `event.eventRef` offers the five aliases plus the events of the last `GET /schedule/events?limit=10` poll labelled `title (status)`.
- **D6 Display-only settings are not options.** Stream Deck settings that only affect the drawn key (`showDuration`, `sourceLabel`, `refreshMs`, `resolution`, `showTitle`, `tapAction`, `holdMs`, `holdToSave`, `showSnapshot`) are not Companion options; their effect is provided by variables, presets and the connection's preview settings. `preset.label` (EC20) is kept because it feeds the preset's second line.
- **D7 Feedback ids follow COMPANION-PARITY.md §9** (snake_case: `recorder_state`, `stream_state`, `layout_active`, …) plus the display-only names `preview`, `system`, `audio`; the legacy camelCase ids are converted by the upgrade script. Variable ids follow §9 too. Action ids are the Stream Deck suffixes.
- **D8 Poll interval in milliseconds.** New config field `poll_interval` ("Poll interval (ms)", default 2000, min 500, max 300000) replaces `pollfreq` (seconds); the upgrade script converts `pollfreq * 1000`. Failure backoff ×2 per consecutive failed poll, capped at 15 s, reset by the first success.
- **D9 Legacy Pearl API fallback stays.** It is request-layer behaviour, not a control. `use_api_v2` stays (last in the form); on legacy firmware the v2-only actions log a warning and no-op, as today.
- **D10 Preview settings stay module-wide.** `preview_interval` (s, 0 disables) and `preview_width` are kept as they are; the Stream Deck per-key `refreshMs` / `resolution` have no Companion equivalent.
- **D11 Absolute gain/delay legacy actions convert to nudges.** `inputAudioGain` / `inputAudioDelay` become `audio` with `control` gain/delay, `direction: up`, `step: 1` and the upgrade log says the absolute value is not carried over; EC20 `setAiTracking` with a blank `enable` becomes `tracking` with `op: toggle`.
- **D12 `refreshPoll` is removed.** The Stream Deck refresh is a tap on a display key; Companion polls at `poll_interval` and after every action.
- **D13 Legacy instances are reported once.** Upgrade scripts cannot log; they push the removed ids into an exported array which `init()` logs at `warn` once per module start.
- **D14 Toggle semantics.** Recorder: start when the state is stopped/disabled/error/unknown, stop when started/starting/paused; `all` toggles from the aggregate (any recorder active → stop all). Stream: start when stopped/error/unknown, otherwise stop; `all` = any publisher started/starting/listening → stop all. Event: running → pause, paused → resume, scheduled → start, otherwise log and no-op. Tally: lit (status on or action ≠ off) → off, else on. Tracking, flip, EC20 stream: invert the polled value (flip prefers the value sent within the last 2 s).
- **D15 Preset categories.** One category per Stream Deck action (Pearl: Recording, Streaming, Layouts, Single touch, Bookmarks, Previews, Outputs, Configuration presets, CMS events, System, Power, Audio, Storage; EC20: Pan / Tilt, Zoom, Focus, Camera presets, Tracking, Presenter, Tally, White balance, Exposure, Picture, Flip, Streaming). The `preset_categories` upgrade sets every new category on.
- **D16 Versions.** Pearl 3.0.0, EC20 1.0.0. Unreleased entries are written under those headings with the date of the final commit.
